## 9.1 环境要求

## 9.3 部署步骤（实际执行记录）

### 9.3.1 本地准备

```bash
cd frontend && npm ci && npm run build && cd ..
tar -czf apa.tgz --exclude=node_modules --exclude=.venv --exclude=.git \
    --exclude=data --exclude=.env .
scp apa.tgz root@<server>:/tmp/
```

### 9.3.2 服务器初始化

```bash
mkdir -p /opt/academic-paper-assistant
tar -xzf /tmp/apa.tgz -C /opt/academic-paper-assistant
cd /opt/academic-paper-assistant
cp .env.example .env && vim .env      # 填写 LLM_API_KEY、ADMIN_*
bash deploy/install.sh
```

`install.sh` 依次完成：

1. 校验 `.env` 与 `frontend/dist/index.html` 是否存在；
2. 创建系统用户 `apa`（无登录 shell）；
3. 创建 venv 并安装依赖（默认走腾讯云 PyPI 镜像，可用 `PIP_INDEX` 覆盖）；
4. 修正 `data/` 与 `.env` 的属主与权限；
5. 安装 `apa.service`，`daemon-reload`，`enable --now`；
6. 打印服务状态并请求 `/api/health` 自检。

### 9.3.3 systemd 单元

```ini
[Unit]
Description=Academic Paper Assistant v2
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=apa
Group=apa
WorkingDirectory=/opt/academic-paper-assistant/backend
EnvironmentFile=/opt/academic-paper-assistant/.env
ExecStart=/opt/academic-paper-assistant/.venv/bin/python -m uvicorn \
    app.main:app --host 0.0.0.0 --port 80 --proxy-headers --forwarded-allow-ips=*
Restart=always
RestartSec=5
AmbientCapabilities=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
```

要点：

- 以非 root 的 `apa` 运行，仅授予绑定 80 端口的能力（`CAP_NET_BIND_SERVICE`）；
- `Restart=always` 保证异常退出后自动拉起；
- `EnvironmentFile` 让 systemd 与 Python 读取同一份配置。

## 9.6 部署中发现的问题

### 外网 80 端口（已放行并验证）

| 项 | 内容 |
|---|---|
| 现象 | 服务启动后，服务器本机 `curl http://127.0.0.1/` 正常，但外部访问 `http://101.200.54.74/` 超时；`ufw` 未启用、`iptables` 默认 ACCEPT，排除主机防火墙 |
| 判断 | 云厂商**安全组**未放行 80 端口（仅 22 端口可达） |
| 处理 | 在云控制台为实例安全组添加入站规则：`TCP:80`，来源 `0.0.0.0/0` |
| 验证 | 放行后从外部网络访问，`GET /api/health` 返回 200；`/`、`/assets/index-*.js`、`/assets/index-*.css` 均返回 200；通过公网地址调用登录接口成功 |
| 结论 | 应用侧无监听或防火墙问题；该问题属基础设施配置，已闭环 |

放行前后的对比数据（同一台机器、同一服务）：

| 检查项 | 放行前 | 放行后 |
|---|---|---|
| `tcp 101.200.54.74:80` | 连接超时 | 可连接 |
| `GET http://101.200.54.74/api/health` | 超时 | 200，`{"status":"ok"}` |
| `GET http://101.200.54.74/` | 超时 | 200，返回 SPA 入口 |
| `GET /assets/index-GdMY3Yb5.js` | — | 200，443,467 字节 |
| `GET /assets/index-DjuNAxYR.css` | — | 200，29,808 字节 |
| `POST /api/auth/login`（公网） | — | 200，返回 JWT |

### .env 权限（已修复）

见文档 08 的 BUG-03。根因是安装脚本只改权限未改属主，服务以 `apa` 运行导致无法读取 `.env`。修复后服务一次启动成功。

## 9.7 日常运维

```bash
systemctl status apa            # 状态
systemctl restart apa           # 重启（会中断进行中的生成，重启后标记为失败可重试）
journalctl -u apa -f            # 实时日志
journalctl -u apa --since "1 hour ago"
```

### 备份

```bash
# 在线备份数据库（不阻塞读写）
sqlite3 /opt/academic-paper-assistant/data/apa.db ".backup /root/apa-$(date +%F).db"
# 备份配置与密钥
tar -czf /root/apa-conf-$(date +%F).tgz -C /opt/academic-paper-assistant .env data/jwt_secret
```

### 升级

```bash
# 本地重新构建前端并打包，上传后：
systemctl stop apa
tar -xzf apa.tgz -C /opt/academic-paper-assistant --exclude=.env --exclude=data
.venv/bin/pip install -r backend/requirements.txt
systemctl start apa
curl -fsS http://127.0.0.1/api/health
```

数据库结构变更通过 `CREATE TABLE IF NOT EXISTS` 幂等建表，新版本启动时自动补齐缺失表；如需加列，应在 `db.init_db()` 中加入兼容迁移。

### 修改管理员密码

当前版本没有内置改密接口，可通过重建管理员记录完成：

```bash
cd /opt/academic-paper-assistant/backend
../.venv/bin/python -c "
import sys; sys.path.insert(0,'.')
from app import db
from app.security import hash_password
db.execute('UPDATE users SET password_hash=? WHERE email=?', (hash_password('新密码至少8位'), 'admin@apa.local'))
print('updated')
"
systemctl restart apa
```

## 9.8 安全加固建议

1. **尽快修改初始管理员密码**，并把 `ALLOW_REGISTRATION` 改为 `false`（如仅本人使用）；
2. 绑定域名后配置 HTTPS（Caddy 自动证书或 Nginx + certbot），避免 JWT 明文传输；
3. 安全组仅放行 80/443，SSH 限制来源 IP；
4. 定期备份 `data/` 与 `.env`；
5. 如对外提供服务，建议在反向代理层增加登录失败限流。

## 9.9 故障排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 服务反复重启 | `.env` 权限、端口占用、依赖缺失 | `journalctl -u apa -n 100` |
| 502/503 | 模型密钥错误或额度不足 | 页面「设置 → 测试模型连通性」 |
| 生成卡在 researching | 服务器无法访问文献源 | `curl -I https://api.openalex.org` |
| 导出 PDF 中文空白 | 阅读器不支持 CID 字体 | 换用 Chrome/Edge/Adobe 打开 |
| 登录后立即退出 | 系统时间偏差导致 JWT 过期判定异常 | 校准 NTP |
| 页面 404（刷新子路由） | 未构建前端或 dist 缺失 | `npm run build` 后重启 |
