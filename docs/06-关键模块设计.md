## 6.1 模型适配层（llm.py）

### 6.1.1 设计目标

- 一套代码同时支持 OpenAI 兼容接口与 Anthropic Messages API；
- 上游抖动（429 / 5xx / 超时）不能让用户直接失败；
- 模型返回的 JSON 必须能被程序可靠解析。

### 6.1.2 协议差异

| 项目 | OpenAI 兼容 | Anthropic |
|---|---|---|
| 路径 | `{base}/chat/completions` | `{base}/v1/messages` |
| 认证 | `Authorization: Bearer` | `x-api-key` + `anthropic-version` |
| 系统提示 | `messages[0].role = system` | 顶层 `system` 字段 |
| 输出 | `choices[0].message.content` | `content[].text` 拼接 |
| 用量 | `usage.prompt_tokens / completion_tokens` | `usage.input_tokens / output_tokens` |

`LLMClient.complete()` 在内部完成分支，对上只暴露 `LLMResult(text, model, tokens_in, tokens_out)`。

### 6.1.3 重试策略

```python
for attempt in range(1, max_retries + 1):
    try: 调用
    except (Timeout, TransportError): 退避 min(2**attempt, 8) 秒
    except HTTPStatusError as e:
        429/5xx → 尊重 Retry-After，否则退避 min(2**attempt, 10)
        其他 4xx → 直接失败（重试无意义）
```

最多 3 次，整体失败后向上抛出 `LLMError`，由流水线把论文标记为 `failed` 并记录可读原因。

### 6.1.4 JSON 提取与修复

模型经常把 JSON 包在 ```json 代码块里，或在前后加一句解释。`extract_json()` 依次尝试：

1. 去掉代码围栏后直接 `json.loads`；
2. 截取第一个 `{` 到最后一个 `}`（或 `[` `]`）再解析；
3. 仍失败则发起一次「修复调用」：把原回答作为 assistant 消息回传，要求「只输出合法 JSON」，温度设为 0。

这条修复路径用于兜底：实际生成中偶发模型在 JSON 前后附加解释文字的情况，可自动纠正而无需重跑整篇。

## 6.2 文献检索层（literature.py）

### 6.2.1 数据源对比

| 源 | 是否需要密钥 | 覆盖 | 特点 |
|---|---|---|---|
| OpenAlex | 否 | 2.5 亿+ 作品 | 元数据全、有摘要倒排索引，首选 |
| Crossref | 否 | DOI 注册库 | 期刊卷期信息准确 |
| arXiv | 否 | 预印本 | 计算机/物理最新成果 |
| Semantic Scholar | 是 | 综合 | 引用关系强，但匿名限流严格（429） |

默认启用前三个，配置 `SEMANTIC_SCHOLAR_API_KEY` 后自动加入第四个。

### 6.2.2 归一化

四个源的响应结构完全不同，统一映射为：

```json
{"title","authors","year","venue","doi","url","abstract","citations","type","source"}
```

其中 OpenAlex 的摘要是「倒排索引」`{word: [positions]}`，需要按位置重建句子：

```python
positions = sorted((pos, word) for word, ps in index.items() for pos in ps)
abstract = " ".join(word for _, word in positions)
```

### 6.2.3 去重与排序

去重键：标题规范化（小写、非字母数字转空格、压缩空白）；标题过短（< 8 字符）直接丢弃。

合并规则：同一条文献被两个源命中时，互补字段（DOI、URL、期刊、年份）取非空值，摘要取更长的一份，引用数取最大值，并记录命中次数。

排序规则（`_hits` 降序 → `_rank` 升序 → 引用数降序）：

1. 多个源都排在前面的文献优先——这是相关性的强信号；
2. 同源内保持原始相关度顺序——比单纯按引用数排序更贴近主题；
3. 引用数只作为最后的并列打破条件。

> 早期版本按「是否有摘要 + 引用数」排序，导致与主题弱相关的文章也能排进前列；改为相关性优先后，返回结果的前几条均为与选题直接相关的文献（可在「文献检索」页面复现）。

### 6.2.4 缓存

- 键：`sha256(query.lower(), limit, year_from, sorted(sources))`；
- 值：合并后的文献数组；
- TTL：72 小时（`LITERATURE_CACHE_TTL_HOURS`）；
- 目的：同一选题短时间重复生成时引用一致，也避免对上游的重复请求。

### 6.2.5 失败隔离

三个源用 `asyncio.gather` 并发，每个都包在 `_guarded()` 里：

```python
async def _guarded(coro, source):
    try:
        return source, await coro
    except Exception:
        return source, []
```

任何单源超时、DNS 失败、限流都只影响该源，整体检索照常返回。

## 6.3 引用格式化（citations.py）

### 6.3.1 姓名解析

四种格式对姓名的要求不同，先统一解析为 `(family, given)`：

```python
"Ashish Vaswani"  → ("Vaswani", "Ashish")
"Vaswani, Ashish" → ("Vaswani", "Ashish")
"李明"             → ("李明", "")        # 中文名整体视作姓氏
```

> 这是本项目实际修复过的一个缺陷：初版把 `parts[:-1]` 当作姓，导致 "Ashish Vaswani" 输出为 "Ashish, V."。单元测试 `test_apa_keeps_author_year_and_doi` 捕获了它。

### 6.3.2 四种格式

| 格式 | 作者 | 年份位置 | 示例 |
|---|---|---|---|
| APA 7 | `Vaswani, A., & Shazeer, N.` | 作者后括号 | `Vaswani, A. (2017). Attention is all you need. *NeurIPS*. https://doi.org/...` |
| MLA 9 | `Vaswani, Ashish, et al.` | 末尾 | `Vaswani, Ashish, et al. "Attention is all you need." *NeurIPS*, 2017.` |
| IEEE | `A. Vaswani, N. Shazeer` | 末尾 | `[1] A. Vaswani, N. Shazeer, "Attention is all you need," *NeurIPS*, 2017.` |
| GB/T 7714 | `VASWANI A, SHAZEER N` | 文献类型后 | `[1] VASWANI A, SHAZEER N. Attention is all you need[J]. NeurIPS, 2017.` |

缺失字段的处理：无年份写 `n.d.`；无作者时 APA 直接以年份开头；无 DOI 时退回 URL；URL 与 DOI 都没有则省略链接。

### 6.3.3 文献类型标记

GB/T 7714 需要 `[J]`（期刊）/`[C]`（会议）等标记。当前按 `type` 字段映射：`article` → `[J]`，其余 → `[C]`；预印本归入 `[J]` 以免误标。

## 6.4 导出模块（export.py）

### 6.4.1 DOCX

使用 `python-docx`，排版参数：

| 项目 | 值 |
|---|---|
| 页边距 | 上下 2.54 cm，左右 3.0 cm |
| 标题 | 18 pt 加粗，居中，黑体 |
| 一级标题 | 14 pt 加粗，黑体 |
| 正文 | 12 pt，1.5 倍行距，首行缩进 0.74 cm（2 字符），两端对齐 |
| 摘要 | 10.5 pt |
| 参考文献 | 10.5 pt，悬挂缩进 0.74 cm |
| 中文字体 | 正文宋体（`w:eastAsia`），标题黑体 |

关键点：`python-docx` 默认只设置西文字体，必须显式写入 `w:rFonts/@w:eastAsia`，否则 Word 中中文会回退到默认字体。

### 6.4.2 PDF

使用 `reportlab`，中文通过 CID 字体 `STSong-Light` 注册，无需在服务器安装字体文件：

```python
pdfmetrics.registerFont(UnicodeCIDFont("STSong-Light"))
```

正文 11 pt / 行距 18 pt，参考文献单独起页并使用悬挂缩进。文本经 XML 转义后再交给 `Paragraph`，避免摘要中的 `&`、`<` 破坏排版。

### 6.4.3 Markdown 与 BibTeX

- Markdown 保留标题层级，便于导入 Typora/Obsidian 继续编辑；
- BibTeX 每条文献生成 `@article{key, ...}`，key 由「第一作者姓 + 年份 + 标题首词」组成，保证可读且基本唯一。

## 6.5 安全模块（security.py）

```python
def hash_password(password: str) -> str:
    if len(password) < 8:
        raise ValueError("password must contain at least 8 characters")
    return bcrypt.hashpw(password.encode()[:72], bcrypt.gensalt(rounds=12)).decode()

def verify_password(password, password_hash) -> bool:
    try:
        return bcrypt.checkpw(password.encode()[:72], password_hash.encode())
    except (ValueError, TypeError):
        return False
```

设计说明：

- bcrypt 只处理前 72 字节，显式截断保证跨平台行为一致；
- cost=12 约 250 ms/次，足以抵抗离线爆破，又不会让登录明显变慢；
- 校验函数对损坏的哈希返回 `False` 而不是抛异常，避免登录接口 500；
- JWT 使用 HS256；密钥缺失时自动生成 48 字节随机串并以 600 权限写入 `data/jwt_secret`，保证重启后会话不失效。

## 6.6 模块间依赖

```
pipeline ──► llm ──► httpx
    │          ▲
    ├──► prompts ──► citations
    ├──► literature ──► httpx + db(cache)
    └──► citations
routers/papers ──► export
export ──► (docx, reportlab)
```

依赖是单向的：`services` 不导入 `routers`，`db` 不导入 `services`，因此每个模块都可单独测试（见 `backend/tests/`）。
