## 10.3 v1 的实际能力与局限

v1 已经具备有价值的探索：多源文献检索、学术写作规则知识库、提示词工程、DOCX 排版、前端四页面。但作为「可交付的系统」存在结构性缺口：

| 维度 | v1 状态 | 影响 |
|---|---|---|
| 数据持久化 | 论文存在进程内 `dict` | 重启即丢失 |
| 账户 | 无 | 任何人可访问，无法公网部署 |
| 生成过程 | 一次性后台任务，无进度 | 用户只能等，失败无提示 |
| 章节编辑 | 无 | 改一处只能整篇重来 |
| PDF 导出 | 依赖 `docx2pdf`（需要 Word） | Linux 服务器不可用 |
| 前端 | 依赖未声明的类型、构建失败 | 无法产出部署产物 |
| 依赖清单 | 根目录 requirements 与代码不一致 | 新环境难以复现 |
| 测试 | 5 个手工脚本，依赖真实 API | 无法作为回归测试 |

### 10.4.2 变更（Changed）

| 项目 | v1 | v2 |
|---|---|---|
| 生成入口 | 单次后台任务 | 阶段化流水线 + 任务管理器 |
| 文献排序 | 有摘要优先 + 引用数 | 多源命中 → 源内相关度 → 引用数 |
| 长度控制 | `words × 2.2` 统一 token 预算 | 按语言分别计算 + 提纲重标定 |
| PDF 生成 | `docx2pdf`（需 Word） | `reportlab` + CID 中文字体 |
| 数据存储 | 内存 dict | SQLite（WAL） |
| 前端构建 | 未纳入流程 | `tsc` 严格检查 + Vite 构建 |
| 依赖管理 | 根目录 `requirements.txt` | `backend/requirements.txt` + `requirements-dev.txt` |

### 10.4.5 安全（Security）

| 项目 | 措施 |
|---|---|
| 密码 | bcrypt cost=12，最短 8 位，72 字节截断 |
| 令牌 | HS256，14 天有效，密钥自动生成并 600 落盘 |
| 越权 | 每个论文接口校验归属 |
| 密钥 | 只从环境读取，接口不回显，仓库 `.gitignore` 排除 `.env` |
| 路径 | 静态资源目录穿越校验 |
| 错误 | 全局异常处理，不返回堆栈 |

## 10.6 数据兼容性

v1 没有持久化，因此不存在数据迁移问题。v2 的数据库由 `CREATE TABLE IF NOT EXISTS` 创建，升级时不会覆盖已有数据。
