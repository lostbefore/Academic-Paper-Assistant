## 00.3 立项与方案

### 00.3.1 起点

最初的动机很具体：大模型能写论文，但写出来的东西**不能查**——参考文献查无此文，数据凭空出现，读者无法判断哪句话有出处。因此目标不是「生成得更快」，而是「让生成过程有据可查」。

由此确定三条边界：

1. 参考文献必须来自真实检索，不允许模型自行生成条目；
2. 不生成实验数据、问卷数据或统计显著性结果；
3. 生成的稿件必须可编辑、可导出、可追溯，而不是一段只能看的文本。

### 00.3.2 技术选型

| 决策点 | 选择 | 备选 | 理由 |
|---|---|---|---|
| 后端框架 | FastAPI | Flask / Django | 原生 async，适合并发检索与流式输出 |
| 前端 | React + TypeScript | Vue / 模板渲染 | 组件化，适合多步骤表单与长文档渲染 |
| 文献源 | OpenAlex / Crossref / arXiv | 只用 Semantic Scholar | 三者免密钥、覆盖互补；S2 限流严格 |
| 文档导出 | python-docx + reportlab | LibreOffice 转换 | 服务器无需安装办公套件 |
| 存储 | SQLite | MySQL / PostgreSQL | 单机部署、零运维，数据量级足够 |

## 00.4 检索与写作链路

### 00.4.1 文献检索

三个数据源的响应结构完全不同，先统一归一化为「标题 / 作者 / 年份 / 期刊 / DOI / 摘要 / 引用数」，再做去重与排序：

- 去重键：标题规范化（小写、非字母数字转空格、压缩空白）；
- 合并规则：同一条文献被多个源命中时，互补字段取非空值，摘要取更长的一份；
- 排序规则：多源命中优先 → 源内相关度 → 引用数。

这一步决定了后面所有引用的质量，因此在这一阶段投入的时间最多。

### 00.4.2 分阶段生成

早期尝试过「一次调用生成全文」，但正文超过约 3000 字后模型开始丢失前文约束，且一次调用要等数分钟。于是改为分阶段：

1. **提纲**：输出结构化 JSON（研究问题、方法、六节目标与字数）；
2. **分节写作**：每节独立调用，后一节参考前节摘要；
3. **摘要**：基于已完成正文生成；
4. **文献表**：由程序按检索元数据格式化，不经过模型。

每写完一节立即落库，任何一节失败都不影响已生成内容。

### 00.4.3 长度与引用控制

- **长度**：按语言分别估算 token 预算（中文按字符、英文按词），并在提示词中给出区间；
- **引用**：文献在提示词中以编号出现，模型只能引用这些编号；文献表由程序生成，因此不会出现不存在的条目；
- **缺失**：检索为空时明确告知模型「无可用文献」，正文不做引用标注，而不是让模型编造。

## 00.5 界面与文档导出

### 00.5.1 页面

按使用顺序组织：登录 → 工作台 → 新建论文（三步向导）→ 论文查看器（正文 / 参考文献 / 过程日志三视图）→ 文献检索 → 设置。

关键交互：

- 生成过程实时显示阶段与进度，失败给出可读原因；
- 任意章节可在线编辑，也可带着补充要求单独重写；
- 导出四种格式，每种独立触发、独立提示。

### 00.5.2 导出

| 格式 | 实现 | 要点 |
|---|---|---|
| DOCX | python-docx | 中文字体需显式写入 `w:eastAsia`，否则 Word 会回退字体；正文首行缩进 2 字符、参考文献悬挂缩进 |
| PDF | reportlab | 用 CID 字体 `STSong-Light` 显示中文，服务器无需安装字体文件 |
| Markdown | 直接拼接 | 便于二次编辑与导入其他工具 |
| BibTeX | 按元数据生成 | key 由「第一作者姓 + 年份 + 标题首词」组成 |

> PDF 早期依赖 `docx2pdf`（需要安装 Word），在 Linux 服务器上不可用，后改为 reportlab 直接生成。

## 00.6 整合与自测

### 00.6.1 串联完整链路

把检索、提纲、写作、导出串成一条可重复执行的流程：输入选题 → 检索 → 提纲 → 分节写作 → 摘要 → 文献表 → 导出。早期由命令行脚本驱动，每一步的中间结果落盘，便于单独复跑与对比。

### 00.6.2 自测方式

| 脚本 | 验证内容 |
|---|---|
| 	est_literature_search.py | 固定选题的多源检索，检查条数、去重与字段完整性 |
| 	est_image_search.py / 	est_image_system.py | 图片检索与图表生成 |
| 	est_chinese_format.py | DOCX 中文字体与段落格式 |
| 	est.py | 端到端样例：从选题到导出 |

每次修改提示词或导出逻辑后重跑上述脚本，对比输出差异。这些脚本保留在 legacy/ 目录中。

### 00.6.3 定稿

三轮打磨：第一轮调整章节结构，第二轮修改提示词（长度、引用、语气），第三轮处理导出格式（字体、缩进、文献表编号）。

## 00.7 复盘

### 做对了什么

1. **先定失败模式再定架构**：每个模块都能对应到一个具体问题，没有为了「看起来专业」而引入多余组件；
2. **状态落库**：进度、章节、事件都写进数据库，因此任务可以放在进程内，重启后也能自愈；
3. **用脚本回归**：提示词与导出格式的改动很容易引入倒退，固定样例比肉眼可靠；
4. **部署脚本化**：权限、端口这类低级错误只会在第一次部署时踩一次，脚本固化后不会重复。

### 遗留问题

| 问题 | 现状 | 计划 |
|---|---|---|
| 修改密码 | 只能脚本重置 | 增加改密接口 |
| 参考文献真伪反查 | 依赖检索元数据 | 接入 Crossref 校验 DOI 存在性 |
| PDF 中文字体 | CID 字体，个别阅读器提示缺失 | 改为内嵌 Noto CJK 子集 |
| 并发压测 | 仅验证 2 并发 | 补 10 并发以上的压测 |
| 开发期版本记录 | 以本地开发为主，未持续提交 | 后续按功能分支提交，保留过程记录 |
