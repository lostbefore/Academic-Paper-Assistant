## 2.1 设计原则

系统在架构上遵循五条约束，后文的每个决策都可以回溯到其中一条：

| 编号 | 原则 | 落地方式 |
|---|---|---|
| D1 | 单进程可运行 | 前端构建产物由 FastAPI 托管，不强制引入 Nginx/Redis |
| D2 | 状态可恢复 | 所有进行中的任务状态落库，进程重启后不出现「假运行」 |
| D3 | 失败要隔离 | 文献源、单节生成、导出格式互不拖累 |
| D4 | 边界要清晰 | router 只做参数与权限，业务在 service，SQL 在 db |
| D5 | 不隐藏成本 | 每次模型调用的 token 数、每次检索的条数都记录下来 |

## 2.3 部署架构

```
                 Internet
                    │  HTTP :80
        ┌───────────▼────────────┐
        │  systemd: apa.service  │  非 root 用户 apa
        │  uvicorn (1 worker)    │  CAP_NET_BIND_SERVICE
        │  ├─ /api/*  → FastAPI  │
        │  └─ /*      → dist/    │
        └───────────┬────────────┘
                    │
        ┌───────────▼────────────┐
        │  /opt/academic-paper-  │
        │  assistant/            │
        │   ├─ .venv             │
        │   ├─ backend/app       │
        │   ├─ frontend/dist     │
        │   ├─ data/apa.db       │
        │   └─ .env (600, apa)   │
        └────────────────────────┘
```

单 worker 的选择是有意的：生成任务以 `asyncio.Task` 存在于进程内，多 worker 会导致任务与 SSE 分散在不同进程。当前并发上限由 `MAX_CONCURRENT_JOBS` 控制（默认 2），单机 1.7 GB 内存可稳定支撑。

## 2.4 技术选型

| 层次 | 选型 | 备选 | 选择理由 |
|---|---|---|---|
| Web 框架 | FastAPI | Flask / Django | 原生 async，SSE 与后台任务自然；自动 OpenAPI |
| 数据库 | SQLite(WAL) | PostgreSQL / MySQL | 单机部署零运维，WAL 支持读写并发；数据量级（个人写作）足够 |
| ORM | 无（原生 SQL + 参数化） | SQLAlchemy | 表少、查询简单，避免 ORM 抽象成本与 N+1 |
| 前端 | React 18 + TS + Vite | Vue / Next.js | 团队熟悉，构建快，SPA 无需 SSR |
| 样式 | Tailwind CSS | Ant Design | 定制成本低，深色模式一行 class 切换 |
| 模型协议 | OpenAI 兼容优先 | 只支持单一厂商 | 一套代码适配 DeepSeek/OpenAI/Kimi/通义等，降低供应商锁定 |
| 文献源 | OpenAlex + Crossref + arXiv | 只接 Semantic Scholar | 三者均免密钥、覆盖互补；S2 有严格限流 |
| 文档导出 | python-docx + reportlab | LibreOffice 转换 | 服务器无需安装办公套件，内存占用低 |

## 2.6 关键设计决策

### ADR-01 用 SSE 而不是 WebSocket

- **背景**：生成过程需要实时展示阶段与日志。
- **决策**：Server-Sent Events，单向推送，`fetch` + `ReadableStream` 消费。
- **理由**：数据流是单向的（服务端→客户端），SSE 自带断线重连语义、走普通 HTTP、可穿透多数代理；WebSocket 需要额外的心跳与重连管理。
- **代价**：`EventSource` 不能带自定义头，因此前端改用 `fetch` 读取流，并支持 `?token=` 兜底。

### ADR-02 生成任务放在进程内

- **背景**：需要后台执行 30–60 秒的生成。
- **决策**：`asyncio.create_task` + 信号量限流，任务表只存在内存，状态存在 SQLite。
- **理由**：无需引入 Celery/Redis，部署简单；状态已落库，进程崩溃后可由启动自检修正。
- **代价**：不支持多 worker 水平扩展——这是当前阶段的明确取舍。

### ADR-03 章节逐节落库

- **背景**：一次生成六节，任一节失败会浪费时间与 token。
- **决策**：每写完一节立即写 `papers.sections_json` 并记事件。
- **收益**：失败后已生成内容不丢；前端在生成过程中就能读到部分正文。

### ADR-04 参考文献只来自检索结果

- **背景**：模型编造文献是最严重的问题。
- **决策**：先检索、把结果编号后放进提示词，模型只能引用这些编号；文献表由程序按检索元数据生成，而非模型生成。
- **收益**：文献表 100% 可溯源；即使模型引用错编号，也不会出现不存在的文献条目。

### ADR-05 长度控制按语言分治

- **背景**：同一句「写 800 字」在中文与英文下消耗的 token 差异极大，直接按 `words*2` 估算会导致中文严重超长。
- **决策**：中文按字符预算换算 token（约 0.55 token/字），英文按 2 token/词；并在提示词中给出字数区间。
- **收益**：实测中文偏差从 1.9 倍降到 1.2 倍以内。

### ADR-06 前端构建产物由后端托管

- **背景**：服务器仅 1.7 GB 内存，不适合安装 Node 构建。
- **决策**：本地 `npm run build`，产物随仓库上传，FastAPI 用通配路由回退到 `index.html`。
- **收益**：服务器零 Node 依赖；单端口部署；SPA 深链接可直接访问。

## 2.8 安全设计

| 风险 | 措施 | 位置 |
|---|---|---|
| 密码泄露 | bcrypt cost=12，72 字节截断，校验失败不区分原因 | `security.py` |
| 令牌伪造 | HS256 + 服务端密钥；密钥缺失时自动生成并 600 权限落盘 | `config.py` |
| 越权访问 | 每个论文级接口调用 `owned_paper()` | `deps.py` |
| 路径穿越 | 静态资源解析后必须仍在 `dist/assets` 内 | `main.py` |
| SQL 注入 | 全部参数化查询，无字符串拼接 | `db.py` + routers |
| 密钥回显 | `/api/status` 只返回 `llm_configured` 布尔值 | `routers/meta.py` |
| 错误信息泄露 | 全局异常处理器统一返回 `Internal server error` | `main.py` |
| 暴力注册 | 可关闭注册；论文数量上限 | `config.py` |

## 2.9 扩展性考虑

当前架构为后续演进预留了三个方向：

1. **换库**：所有 SQL 集中在 `db.py` 与路由的参数化语句中，迁移 PostgreSQL 时只需替换连接层；
2. **加数据源**：`literature.search_literature()` 的 `sources` 参数即插拔点，新增源只需实现一个返回统一结构的协程；
3. **加导出格式**：`routers/papers.py::export_paper` 按 `fmt` 分派，新增格式实现一个 `build_*` 函数即可。
